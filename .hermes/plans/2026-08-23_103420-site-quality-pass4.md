## Part A — OPDS 2.0 fix (user-reported broken)

### Research note for implementer (read first)

OPDS 2.0 (https://specs.opds.io/opds-2.0) key requirements, diffed against what the feed serves today:

- OPDS 2.0 feeds are **Atom XML** but MUST use the `Readium Web Publication Manifest`-compatible
  entry points: root feed carries `rel="self"` with `type="application/atom+xml;
  profile=opds-catalog; kind=acquisition"` **and** an alternate JSON manifest via
  `rel="alternate" type="application/webpubmanifest+json"` (the "manifest" link).
  Simplest robust compliance path used by Calibre/KA1 readers: keep Atom, add the
  `opds:2.0`-style links, ensure EVERY entry has:
  - `<id>` (urn or https URL)
  - `<title>`, `<updated>`
  - at least one acquisition link with a concrete media type
  - `rel="http://opds-spec.org/image"` cover (optional)
- Critical bug regardless of spec version: acquisition hrefs must be **absolute URLs pointing at
  working file routes**. Today they point at nonexistent `{url_id}/{url_id}.epub` paths.
- Auth: many OPDS clients can't do interactive login. FicHub downloads are anonymous-allowed, so
  the OPDS feed should stay unauthenticated (it is).

```rust
/// Query export_log for the latest export_hash per etype and build absolute
/// acquisition URLs shaped like the web app's (/cache/{etype}/{url_id}?h={hash}).
async fn acquisition_links(state: &AppState, base: &str, url_id: &str) -> Vec<(&'static str, String)> {
    let rows = sqlx::query_as::<_, (String, String)>(
        "SELECT DISTINCT ON (etype) etype, export_hash FROM export_log \
         WHERE url_id = $1 ORDER BY etype, version DESC, created DESC")
        .bind(url_id).fetch_all(&state.db).await.unwrap_or_default();
    let mut out = Vec::new();
    for (etype, hash) in rows {
        let (mime, path) = match etype.as_str() {
            "epub" => ("application/epub+zip", "epub"),
            "pdf" => ("application/pdf", "pdf"),
            "mobi" => ("application/x-mobipocket-ebook", "mobi"),
            "azw3" => ("application/vnd.amazon.ebook", "azw3"),
            "txt" => ("text/plain", "txt"),
            "html" => ("text/html", "html"),
            "docx" => ("application/vnd.openxmlformats-officedocument.wordprocessingml.document", "docx"),
            _ => continue,
        };
        let _ = mime;
        out.push((path, format!("{base}/cache/{path}/{url_id}?h={hash}")));
    }
    out
}
```

## Part E — Merge Requests + Ask-the-Archive into "Ask & Request"

### Design

New unified page `/ask` absorbs `/requests` UX. Flow:
1. User types a natural-language ask ("something like Super Minion but completed").
2. Frontend calls existing `POST /api/search/ask` → returns parsed params + top matched works
   (instant LLM answer).
3. Response renders: (a) "Search link" — a pre-filled `/search?…` deep link generated from the
   parsed params (this is the LLM's reply, always present); (b) matched works as WorkBlurbs.
4. Below, the SAME question is auto-persisted as a request (existing `POST /api/requests`) marked
   `source='ask'`, so humans can add answers: another work (url_id) or another search link
   (parsed params JSON). Answers list merges both kinds; voting/accepting reuses existing
   request answer endpoints unchanged.
5. Old `/requests` routes redirect (308) to `/ask` preserving query/id where sensible
   (`/requests/{id}` → `/ask?q=request:{id}` opens that thread focused).

## Risks / tradeoffs / open questions

1. **OPDS 2.0 strictness**: some readers are 1.1-only. Mitigation: keep 1.x namespace attributes
   alongside 2.0 links (dual-compat), verify against at least one real reader the user owns
   (KOHO/PanCast/etc — ask user which reader they tested with, since "doesn't work" symptom may
   also have been purely the dead download links, which A1 fixes regardless).
2. **include_str! docs registry** bloats binary slightly (~200KB) — acceptable; alternative is
   shipping docs/ dir beside binary and fs reads (config flag later if needed).
3. **Requests merge**: existing request permalinks must not die — 308 shims mandatory before
   deleting anything. Answer payloads need the migration before frontend ships.
4. **Consensus visibility**: making votes public-by-default matches the transparency pillar but
   confirm handles are anonymized (existing code says zero-PII — reuse its anon display logic).
5. **Scope control**: Part F is pull-queue — ship A–E fully before starting F items; each F task
   stops cleanly if time runs out.
